# HackAlem AI — LogicX

MVP конструктора бизнес-задач: рейтинг готовности, каталог, предложения студенческих команд и ручное решение бизнеса.

## Запуск

Нужен Node.js 20+.

```sh
npm install
npm run dev
npm test
npm run build
```

В Windows PowerShell с запретом скриптов используйте `npm.cmd` вместо `npm`.

## Архитектура и данные

- React + Vite + Tailwind; App хранит задачи, команды и отклики.
- TaskForm — конструктор, aiService — текущая AI-заглушка; prompts.txt содержит подготовленные промпты, пока не подключённые к внешнему API.
- Catalog сортирует по результату calculateScore и фильтрует по теме и уровню. TaskDetails показывает полную карточку, форму отклика и решения бизнеса.
- TaskPanel открывает карточку в боковой модальной панели поверх каталога. Панель прокручивается отдельно, заголовок и закрытие закреплены; Escape закрывает панель, фокус возвращается на кнопку задачи. На узком экране панель занимает всю ширину.
- TaskEditor позволяет бизнесу изменить опубликованную задачу. До сохранения виден предварительный рейтинг; каждое изменение сбрасывает флажок подтверждения. Отмена не меняет опубликованную карточку. Сохранение обновляет поля и confirmedAt, сохраняя id, отклики и решения.
- data/initialData.json — новый набор для демонстрации. utils/demoState.js преобразует data → dataAvailable, responses → submissions, solutionIdea → idea и план-массив → строку. Тема берётся из связанного черновика.
- Старый src/data/initialData.json нужен для совместимости с ранее сохранёнными задачами и их откликами.
- localStorage.hackalem_demo_v2 хранит общий снимок. При первом запуске новой версии старые hackalem_tasks переносятся без удаления. При ошибке записи выводится предупреждение.
- Роли переключаются для демонстрации. Авторизации и синхронизации между устройствами нет.

## Рейтинг и каталог

Текущая формула ещё требует приведения к ТЗ: title 10, context 25, expectedResult 25, successCriteria 20, dataAvailable 12, constraints 8. Пустое поле даёт 0; менее 12 символов — 25% веса; иначе вес умножается на `0.7 + 0.3 * min(длина / 200, 1)`. Итог округляется. Уровни пока имеют границы 30/60/85.

Значения readinessScore из исходного JSON не используются. Каталог всегда пересчитывает рейтинг функцией calculateScore. Низкий балл не скрывает задачу и не запрещает отклик. Каждый отклик рассматривается отдельно: можно выбрать несколько команд, отклонить все или вернуть решение на рассмотрение. Автоматического назначения нет.

## Проверка демонстрации

1. В роли «Бизнес» ввести идею, получить вопросы, заполнить карточку и добавить её в каталог. Проверить изменение баллов и позицию.
2. Переключиться на «Команда», найти задачу и нажать «Открыть задачу».
3. Выбрать команду, ввести идею, план, срок и полный HTTP(S)-адрес прототипа. Отправить отклик.
4. Отправить второй отклик от другой команды. Ограничения числа откликов нет.
5. Переключиться на «Бизнес», выбрать один отклик, отклонить другой. При необходимости выбрать оба или вернуть на рассмотрение.
6. Перезагрузить страницу, открыть задачу и проверить сохранность откликов и решений.
7. Проверить фильтры и отклик на задачу с низким рейтингом; пустые поля и некорректная ссылка должны препятствовать отправке отклика.
8. В роли бизнеса открыть задачу с откликами и нажать «Редактировать задачу». Изменить результат и тему; проверить предварительный рейтинг. Без подтверждения сохранение должно показать ошибку.
9. Поставить флажок подтверждения, изменить ещё одно поле — флажок должен сброситься. Подтвердить заново и сохранить. Проверить текст, рейтинг, сортировку, тему и сохранность откликов.
10. Открыть редактор ещё раз, изменить название и нажать «Отменить изменения»: название должно остаться прежним. Перезагрузить страницу и проверить сохранённую версию и решения бизнеса.
11. Открыть карточку из середины каталога: панель должна появиться сразу без прокрутки страницы. Проверить закреплённое закрытие, Escape, перемещение Tab внутри панели и возврат фокуса на задачу после закрытия.

`npm test` проверяет миграцию, связи новых данных, некорректное хранилище, валидацию откликов, выбор нескольких команд, подтверждение изменений, сохранность связей при редактировании и сохранение решений после загрузки. Это проверки логики; сценарий интерфейса выше необходимо пройти в браузере отдельно.
