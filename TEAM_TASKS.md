# Задачи команды

## Проверка версии с реальным API

Перед проверкой обновить main: git pull --ff-only origin main, затем npm install. Создать свой локальный .env по .env.example и запустить npm run dev. Ключи не пересылать через Git. Если .env менялся, перезапустить сервер.

- Участник 2: форма и рейтинг. Проверить слабое описание, 3 AI-вопроса, перенос ответов, подтверждение, сброс подтверждения после правки, запрет публикации во время запроса, отсутствие баллов за прочерки, уровни 40/70/90, сортировку и фильтры. Сравнить вопросы для кофейни и учебного центра; проверить подсказку по известному контексту и сообщение о недостатке фактов.
- Участник 3: каталог и команды. Проверить боковую панель, редактирование/отмену, отправку двух откликов, выбор обеих команд, отклонение и возврат на рассмотрение, низкий рейтинг без блокировки отклика, сохранение после F5. Отклики и решения должны сохраняться после редактирования задачи.
- Каждый записывает: шаги, ожидание, фактический результат, скриншот при визуальной ошибке. Изменения кода — в отдельных ветках от обновлённой main, без перезаписи AI-файлов старой версией.
- npm test и npm run build — бесплатные локальные проверки. npm run ai:check делает два платных запроса; для обычной проверки повторять его не требуется.

## Текущий статус AI

OpenAI подключён через серверный /api/ai (Vite dev/preview). Ключ только в локальном .env. Проверены вопросы и подсказка через HTTP. Тесты: 19, сборка успешна. Дальше — браузерная проверка и оценка ответов на разных примерах. Ниже сохранён статус предыдущего этапа.

## Статус интеграции

Из origin/feature/task-quality выборочно перенесены рейтинг и бейдж; полная форма объединена с нашей схемой и защитой AI-запросов. Сохранены рабочие App, TaskDetails, редактор и боковая панель вместо оборванного TaskDetails из ветки команды. Это перенос изменений в рабочие файлы, а не git merge; коммита интеграции пока нет.

Реализованы ответы с переносом в карточку, единая расшифровка рейтинга, подтверждение создания и правок, защита от публикации во время запроса и валидация AI-ответов. Пустые заглушки не начисляют баллы. 15 тестов и сборка проходят. Остались реальный API и браузерная проверка. Следующие правки участников нужно делать на основе согласованной версии интеграции, чтобы не вернуть старые App и TaskDetails.

AI-контракт сохраняет questions: string[] и extractedFields. Дополнительно поддерживается questionFields: string[] для привязки ответов; без него пользователь выбирает поле. Форма валидирует ответы через utils/aiValidation.js. Текущий локальный адаптер не генерирует неизвестные факты; наличие API у команды учтено, подключение отложено по договорённости.

Наш участок: App.jsx, Catalog.jsx, TaskPanel.jsx, TaskDetails.jsx, TaskEditor.jsx, utils/demoState.js, utils/submissions.js, utils/taskEditing.js, tests/workflow.test.js, tests/taskEditing.test.js, README.md.
Реализованы каталог с сортировкой и фильтрами, полная карточка, отклики, ручной выбор нескольких команд, отклонение и отмена решения, сохранение в браузере. Новые данные подключены через адаптер, старые локальные задачи сохраняются.

Добавлен отдельный редактор опубликованной задачи: предварительный рейтинг, подтверждение, отмена без сохранения, сохранение id и всех откликов. После любого изменения поля подтверждение сбрасывается. Проверки логики и сборка выполнены; проверка в браузере остаётся общей задачей команды, так как браузер не подключён к инструментам текущей сессии.

## Участник 2 — карточка и рейтинг

Ветка: feature/task-quality. Файлы: src/components/TaskForm.jsx, src/components/ScoreBadge.jsx, src/utils/calculateScore.js. Можно добавить ScoreBreakdown.jsx и отдельный тест рейтинга.

- Добавить поля need, users, contact, interactionFormat, industry. Сохранить dataAvailable (не переименовывать в data).
- Веса: context + need = 20, dataAvailable = 20, expectedResult = 15, successCriteria = 15, constraints = 10, users = 10, contact + interactionFormat = 10. Название не приносит баллы.
- Уровни: 0–39 Черновик, 40–69 Рабочая, 70–89 Готовая, 90–100 Приоритетная.
- Показать вклад каждого показателя, отсутствующие сведения и предварительный рейтинг. Перед публикацией человек подтверждает карточку; AI-текст сам по себе не считается подтверждением.
- Проверять название и описание, но не запрещать публикацию из-за низкого балла.
- Связать ответы на уточняющие вопросы с редактируемыми полями. Защитить ручной ввод от запоздавших AI-ответов.
- Оставить интерфейс TaskForm({ onSubmit }); calculateScore(task) возвращает как минимум { score, level: { label, badge }, missingFields }. Дополнительные поля разрешены.

Готово, когда: баллы прозрачны, границы 39/40/69/70/89/90 проверены, карточка подтверждается, поля не теряются при публикации. Редактирование опубликованной карточки уже реализовано участником 1 отдельно в TaskEditor. Он использует calculateScore и записывает confirmedAt после ручного подтверждения. Если рейтинг начнёт использовать другую структуру подтверждения полей, согласовать её с участником 1 и обновить оба конструктора вместе.

## Участник 3 — AI

Ветка: feature/ai-builder. Файлы: src/services/aiService.js, prompts.txt. Можно добавить AI-модуль валидации и отдельный тест.

- Использовать подготовленные промпты. Сохранить функции generateClarifyingQuestions(rawDescription) и generateFieldSuggestion(fieldName, currentContext).
- Первая возвращает { questions: string[], extractedFields: { title: string, context: string } }, минимум три уместных вопроса. Вторая возвращает строку.
- Учитывать контекст, не повторять уже отвеченные вопросы. Не выдумывать контакты, сроки, технологии, данные и метрики.
- Поддержать dataAvailable, need, users, contact, interactionFormat и остальные поля формы.
- При недостатке фактов возвращать понятную ошибку/необходимость уточнения; не заполнять поле пустой универсальной фразой.
- Проверять структуру ответов и выдавать понятные ошибки. Заглушка разрешена ТЗ; явно обозначить режим. Для внешнего API нужен серверный обработчик, ключ не помещать в VITE_*.

Готово, когда: два разных описания дают уместные вопросы и подсказки; некорректный ответ обработан; неподтверждённых фактов нет. Изменение формата questions предварительно согласовать с участником 2.

## Общие договорённости

- Новые исходные данные находятся в data/initialData.json; src/data/initialData.json оставлен для миграции старых задач и откликов.
- В приложении задача использует dataAvailable и industry; отклик: id, taskId, teamId, idea, plan (строка), deadline, link, status (pending/accepted/rejected).
- readinessScore из JSON не используется: единственный источник рейтинга — calculateScore.
- Не редактировать чужие файлы без согласования. Не редактировать dist вручную.
- Перед передачей: npm.cmd test и npm.cmd run build. Перед защитой совместно пройти сценарий из README.
